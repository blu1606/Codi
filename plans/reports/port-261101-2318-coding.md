## Rows or parts skipped, with reasons

- **Workspace loading** ("Đang tải bài tập code…" / "Đang tải hướng dẫn code…"): the lesson data is local and
  synchronous. Porting guide rule 7 forbids latency that does not drive a real loading state. The load-error state
  is ported through the real contract validation. The tutor panel and the Tutor page do have a short simulated load,
  because the brief asks for their loading and error states.
- **Draft-save failure** ("Không thể lưu bài làm. Vui lòng thử lại."): the prototype store has no failure source for
  a local save.
- **Prettier formatting**: adding a dependency is out of scope. Real behaviour is kept where it shows: a syntax error
  blocks formatting with the real copy, otherwise indentation is normalised to 2 spaces.
- **Lease (20 s) and 409 "Bài tập đang chạy…"**: the buttons are disabled while a run is in progress, so this state
  cannot be reached. The 2-second cooldown (429) is ported.
- **Lesson picker "· Chưa đủ tiên quyết"**: the lock status belongs to the learning feature store, which this feature
  cannot import (ownership). See the shared change requests.
- **Row 13 conversation list, reply, resolve and reopen**: these live in the lesson player (learning) and the lecturer
  inbox. They are out of this folder.

## Deviations from the mockup docs (for `docs/deviations-from-mockup.md`, controller-owned)

1. C2 solution gate: real. The solution needs `solutionCheck.ok` and either a pass or 3 failed submits whose run
   finished. The mockup allowed it at any time behind a confirm.
2. C3 Python: refused with "Sandbox chưa sẵn sàng" and drafts kept. It is no longer simulated, and the
   "· mô phỏng" label is gone. `Codi.code.run(…, {language:'python'})` resolves `{phase:'unavailable', results: []}`.
3. Grading: `passed` and the score come from the latest submit ("Chỉ lần nộp gần nhất được tính."). The mockup used
   the best score and a sticky pass. `bestScore` is still kept.
4. Hint locks: one line, "Còn N gợi ý mở dần…", instead of one locked line per hint.
5. The hidden-test summary no longer adds "— xem lại bước N" (real exposes nothing about hidden tests).
6. The timeout copy is real ("Quá thời gian chạy (3 giây)." and "Code đã vượt giới hạn 3 giây…").
7. The challenge output is a tab pair, Kết quả kiểm thử / Console. Test rows are collapsed by default.
8. Reset is labelled "Đặt lại" in the editor bar, is always enabled, and uses the real copy. Format no longer shows a
   toast.
9. Tutorial test results print in the console instead of a separate "Kiểm tra bước này" panel. The TOC check means
   the step was visited.
10. Tutor: the title is "Trợ lý AI", the placeholder is "Hỏi trợ lý về bài học…". New: three modes, the "+" context
    menu, the "Yêu cầu" chip, copy, escalate after 👎, "Đã dùng n/3 gợi ý", and the 8-per-60-s limit. A transient
    failure is shown separately from a stored error. The lecturer-waiting copy is now "Bạn sẽ nhận thông báo khi giảng
    viên trả lời.".
11. Selection toolbar: the actions differ for code and for text, as in real.
12. New: the full Tutor page and the launcher popup. Rebuild-only addition: a "Lưu ý khi dùng trợ lý AI" link in the
    panel's empty state, so the disclaimer is reachable even when the lesson player does not render the launcher.
13. Mockup kept where real has nothing: per-instruction-step done markers in "Yêu cầu" and the plain-language
    explanation line under errors.

2. **Learning, lesson player**: render `{Codi.tutor?.launcher(c.id, l.id)}` once per lesson, which gives the real
   round AI button and popup. Put `id="checklist"` on the completion checklist so "Tiếp tục" on the pass card scrolls
   to it. The current fallback is `.ln-checklist, [data-checklist]`. Note that `Codi.code.status(l).done` now follows

   Tutor lesson picker can show "· Chưa đủ tiên quyết".
3. **Lecturer AI**: `Codi.code.run` no longer simulates Python. It resolves `phase: 'unavailable'` with no results,
   so verifying a Python solution yields no expected values (same as real). The JavaScript path and the result shape
   are unchanged. `results[].line` and `durationMs` were added.
4. **Lecturer and analytics**: tutor threads moved from the slice `state.aiLessonChats` to `db.tutorThreads`. Old
   slice threads move over the first time the learner writes to them.
5. **Lecturer AI (done, from your request)**: `Codi.code.view(c, l, { preview: true })` renders a stateless workspace.
   The attempt (drafts, runs, tutorial step, solution view) lives in a module-level memory store per lesson. Nothing is
   written to `Codi.db().codeAttempts` and `Codi.set` is never called; the view only re-renders itself. Editor keys use
   `chp:` / `tup:`, so preview editors never collide with a learner workspace or the tutor's editor lookup, and the AI
   tutor buttons are hidden. The preview state resets on page reload. Calling `view(c, l)` without options behaves as
   before.
6. **Controller**: copy the deviations above into `docs/deviations-from-mockup.md`.
