Admin cancel rules:

- A reason is required ("Lý do huỷ đơn hàng là bắt buộc.").
- Only pending orders can be cancelled ("Chỉ có thể huỷ đơn đang chờ thanh toán (trạng thái hiện tại: …).").
- The order gets `status:'cancelled'`, `cancelledAt`, `cancelReason` and `updatedAt`.
- If `received > 0`, the order also gets `needsReconciliation = true`. The flag is never cleared.
- The timeline gets `{type:'cancelled_by_admin', by: adminId, note: reason}`.
- The learner gets `Codi.notify` with the real title and body, linking to `/dashboard`.
- Toast: "Đã huỷ đơn hàng {code}.".

Timeline labels: per the controller's request, labels are mapped from `type` (created, paid, partial_payment, overpaid, late_payment, expired, failed, cancelled, replaced, refunded, cancelled_by_admin). Unknown types fall back to `t.label || t.note || t.type`. The `needsReconciliation` flag set by commerce is read as-is, never recomputed.

## New seed fields (`server/seed-source/patches/70-admin.js`)

The history ends at seed time (`Date.now()`), so every window has data after a reseed. The PRNG is seeded, so rows are the same each time; only their absolute dates move with the seed time.

**Users:**
- Adds 96 learners with ids `usr-learner-h001…h096` and fields `emailVerified` and `emailVerifiedAt`.
- Existing users get `emailVerified: true` when it is missing.
- The users list grows from 13 to 109 accounts.

**Orders:**
- Adds about 115 rows (`order-h####`, `CODI2####`) with the full contract: `received`, `expiresAt`, `failReason` ('expired'), `cancelledAt`, `cancelReason`, `timeline [{at,type,by,note?}]`, plus `needsReconciliation`, `isBuyNow` and `updatedAt`.
- Vouchers are applied according to their rules and dates.
- Five fixed recent rows cover the queues:
  - one underpaid pending order (500.000 ₫ of 990.000 ₫)
  - one pending order older than 24 hours
  - one expired underpaid order (flagged)
  - one overpaid order (flagged)
  - one order created 8 minutes before seed time
- Late payments are flagged.
- Existing orders get `needsReconciliation: false` when it is missing.

**Enrolments:**
- One row per paid course line, plus free-course rows.
- New fields: `status` ('active' | 'completed'), `completedAt`, `orderId`, `startMode` ('diagnostic' | 'lesson1'), and `pathStatus` ('ready' | 'error') for diagnostic starts.
- Existing rows get `startMode` and `pathStatus` when missing.

**learnerProgress:**
- One row per new enrolment with `completedAt: { lessonId: iso }` and `quizScores`.
- Existing rows get `completedAt` spread between enrolment and `lastActive`.

**New key `studyLog`:** `[{ userId, days: { 'YYYY-MM-DD': { m: minutes, ai?: [latencyMs…], err?, rl? } } }]`, keyed by GMT+7 day.

**New key `checkoutEvents`:** `[{ userId, courseId, kind: 'cart'|'buy_now', at, orderId|null }]`. Every order has its click event; abandoned clicks have `orderId: null`.

Size added to the snapshot: about 250 KB of JSON.
